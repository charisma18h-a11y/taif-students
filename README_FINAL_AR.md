# وش علينا — النسخة المطورة / Midnight Blue

## ما أضيف فعليًا
- ثيم Midnight Blue للواجهة الأساسية ولوحتي الطلاب والإدارة.
- مركز متكامل للطالب مع الإعلانات، التنبيهات داخل الموقع، العد التنازلي لمواعيد الاختبارات والتسليم، بحث المطلوب، وتحديد الإنجاز لكل طالب.
- جدول أسبوعي مبني على مادة وشعبة الطالب. الإدارة تدخل المحاضرات والأوقات يدويًا.
- صفحة مستقلة للمواد على `/courses` مع بحث في الواجبات، وصفحة مجلس الإدارة المستقلة `/board`.
- تبويب «الإعلانات والجدول» بلوحة الأدمن لإضافة وحذف الإعلانات والمحاضرات.
- استخدام بنك المراجعة الحالي، وتحسينات تمييز العناصر المهمة.
- ملف PWA manifest وأيقونات لتثبيت الموقع إن سمح المتصفح بذلك؛ لا توجد إشعارات Push خارج المتصفح.
- الاحتفاظ بإصلاح P2010 في تسجيل ونقل المجموعات.

## طريقة النشر
1. احتفظ بنسخة احتياطية من Supabase ومن المستودع قبل الاستبدال.
2. ارفع **محتويات مجلد site** (وليس المجلد نفسه) إلى جذر GitHub، مع الحفاظ على متغيرات Vercel الحالية.
3. بعد النشر، ادخل بلوحة الأدمن وافتح «الإعلانات والجدول» لإنشاء الجداول الإضافية تلقائيًا. لا توجد أوامر DROP أو TRUNCATE أو تعديل لجداول الطلاب القديمة.
4. راجع Logs: إذا ظهر `portal hub read` راجع صلاحيات مستخدم `DATABASE_URL` لإنشاء الجداول. لا ترسل مفاتيح أو عناوين اتصال.
5. بعد التأكد من الاتصال عبر Prisma فقط، شغّل `SECURITY_AFTER_DEPLOY.sql` في Supabase لحجب وصول المتصفح المباشر للجداول الخاصة. لا تشغّله قبل فحص أي خدمة خارجية تستخدم anon.
6. اختبر حسابين: طالب ينضم لمجموعة ويراه الثاني، جدول الطالب، لوحة الإدارة، تعديل الإنجاز، صفحة المجلس.

## حدود مهمة
- الإشعارات داخل الموقع مستمدة من الإعلانات؛ ليست تنبيهات Push على الجوال، وليست حالة «تمت القراءة» المخزنة.
- تحديد الإنجاز مؤشر شخصي وليس تسليمًا رسميًا للواجب.
- لوحة المواعيد تعرض الاختبارات ذات تواريخ التسليم الموجودة فعلًا في قاعدة البيانات؛ والجدول يُدخل يدويًا.
- جدول المجموعات يحتوي على سجلات قديمة بدون student_id: 30 سجلًا حسب فحص المستخدم الأخير، لم يتم حذفها أو تعديلها في هذه النسخة.
- لم يحدث اتصال بقاعدة بيانات الإنتاج، ويجب اختبار النشر والأمان قبل تعميم الموقع.
